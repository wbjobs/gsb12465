# 共享剪贴板队列

多个浏览器标签页共享一个剪贴板队列：任意标签页复制的文本都会进入队列，其它标签页实时可见并可取出。纯原生 Web API，无任何框架与构建步骤。

## 运行

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000 ，多开几个标签页即可测试
```

注意：`navigator.locks`、`BroadcastChannel`、`IndexedDB` 在 `file://` 或 insecure 上下文下可能受限，请通过 `localhost`（或 HTTPS）访问。

## 功能

- 监听页面 `copy` 事件，选中文本自动入队；也支持手动输入、读取系统剪贴板
- 多标签页实时同步（BroadcastChannel + IndexedDB）
- 取出（复制到系统剪贴板并移除）、删除、清空（保留固定项）、固定/取消固定
- 每个标签页的操作记录（可按标签页筛选）
- 搜索过滤、自动/手动去重
- 队列超长自动截断（默认 100 条，见 `js/utils.js` 中 `MAX_ITEMS`），固定项永不截断

## 架构与关键约束

```
js/utils.js   纯函数：hash、截断、去重（Node 可直接测试）
js/db.js      IndexedDB 封装 —— 唯一事实来源
js/store.js   写操作经 Web Locks 串行化 → 落库 → 广播通知
js/ui.js      DOM 渲染
js/app.js     入口：标签页身份、剪贴板交互、事件绑定
```

- **并发冲突**：所有写操作（复制入队 / 取出 / 删除 / 清空）都先获取
  `navigator.locks` 的排他锁，再在单个 IndexedDB 事务中完成"改数据 + 写操作日志"，
  同时复制与取出不会互相踩踏。
- **关闭不丢 / 刷新一致**：状态只存 IndexedDB，标签页关闭、刷新后从库中全量恢复。
- **消息乱序**：广播消息只是"请重新读库"的触发器，不携带业务数据；
  接收方总是从 IndexedDB 全量重读，乱序、重复、丢失的消息都不会造成数据不一致。
- **离线恢复**：离线期间的操作直接落库（广播失败无影响），恢复后任意一次
  sync / `visibilitychange` / `focus` 触发重读即完成合并，无需冲突解决。
- **标签页身份**：`sessionStorage` 保存 tab id 与名称，刷新不变、标签页间唯一，
  操作记录可归属到具体标签页。

## 验收对照

| 验收标准 | 实现 |
| --- | --- |
| 4 个标签页同时操作一致 | Web Locks 串行化 + 单事务落库 + 全量重读 |
| 关闭后队列不丢 | IndexedDB 持久化 |
| 乱序不重复不丢失 | 广播仅作触发器，状态以库为准 |
| 离线恢复合并正确 | 离线写直接落库，恢复后重读合并 |
| 队列截断正确 | `idsToTrim`：保固定项 + 最新未固定项 |
| 刷新后一致 | 加载时从 IndexedDB 全量恢复 |
